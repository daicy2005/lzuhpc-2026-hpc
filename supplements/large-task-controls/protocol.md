# 单任务大于 LLC 的补测

官方 Mini WorkSteal 要求覆盖“任务远小于 LLC 和远大于 LLC”。机制补测中最大的总数据为 288 MiB，但单任务只有 4.5 MiB，因此另加本组，不能将总数据量冒充单任务大小。

## 固定条件

- 内核、运行时和实验程序直接复用已通过检查的 mechanism-controls-v3 二进制，SHA256 固定，不修改已有程序或策略。
- memory_reuse，seed=194033，4 个元素，每元素 288 MiB，grain=1，passes=4。每个任务为 288 MiB，约为报告 LLC 36 MiB 的 8 倍；总数据 1152 MiB，未超过程序 2 GiB 上限。
- 执行线程固定的对照：2 个线程池线程，controlled_worker=0 或 1；各比较相同线程与另一线程预读。每对只改变 home_worker。
- 动态对照：4 线程，所有任务 home=0、placement=home，不设置 controlled_worker；disabled_yield / immediate 比较，双方空闲处理相同。诊断须出现成功窃取和非 home 执行，否则停止，不把没有迁移写成零局部性损失。

## 数量与边界

6 个条件，各 1 次诊断、1 次预热、5 次正式运行，共 42 次，其中 30 次计时。三对条件的运行顺序先冻结，正式区组交替对内先后次序并轮换各对顺序。全部成功慢样本保留；不按结果补抽样。

开始前检查可用内存至少 3 GiB，沿用连续三次 Windows CPU 不超过 15% 和 Linux 无其他计算任务的检查，最多等 300 秒。采集总预算 900 秒，单进程 90 秒。每个进程完整标量重算，诊断另验证 exact_once、任务归属和工作量；全部条件输入、数据、输出和预读散列一致。诊断、预热与正式计时分开，Linux 与 Windows 导出逐文件核对 SHA256。

本组只补大任务一端，不改变上一组数据。固定执行线程的预读对照量化的是可观测耗时差，动态 off/on 量化的是总效果；均不将全部差值归因于缓存，也不把三个效应作无交互的加法分解。官方允许局部性窗口不成立时该效应接近零，保留负结果。
