# 机制补充实验

这次补测解决两个问题：旧 off/on 的空闲策略不同；旧局部性测试设置 controlled_worker 后关闭了窃取，不能观察动态迁移。原始记录继续保留，新结果另存 mechanism-controls。

## 对照设计

1. **窃取开关**：新增独立 Timing 实现 disabled_yield，只链接到实验程序；关闭窃取且空闲时 yield，与 immediate 一致。不改已有运行时或默认策略。16 线程，两个新输入 (170021,65536)、(176023,98304)，K=256，grain=8/256，concentrated/spread 各做开关对照。
2. **调度路径**：同一 compute_uniform，N=262144、K=16、seed=182027，单线程比较 grain=8/64/4096 的线程池及连续串行循环。三个粒度都整除八路计算内核的宽度，避免引入标量尾部差异。线程池相对连续循环的差包含唤醒、取任务、函数分发、完成通知等；粒度差是增加任务数的增量成本，不拆成每把锁或每个原子的独立成本。建队列和输入初始化不计入 epoch，app 另存。
3. **执行线程固定的预读对照**：memory_reuse，64 个 grain=1 任务、passes=4、seed=188029，总数据分别为 512 KiB、4.5 MiB、288 MiB。每种规模固定执行线程 0 或 1，再比较由相同线程或另一个线程预读。仅改变 home_worker，controlled_worker 保持不变。每个任务分别为 8 KiB、72 KiB、4.5 MiB；大于 LLC 指总数据，不能称每任务大于 LLC。旧实验另有每任务 288 MiB 的记录。
4. **动态窃取检查**：同样三种数据，4 线程，全部 home=0、placement=home，不设置 controlled_worker；在诊断中核实成功窃取和实际非 home 执行。动态测试用于观察总效果，不能用它与串行预读对照的时间差计算纯缓存损失。

## 样本、检查与停止条件

每个条件一次诊断、一次预热、五次独立正式运行；共 35 个条件、245 次运行，其中 175 次计时。正式顺序预先固定，五个区组中轮换条件顺序并反转相邻条件的先后，不根据速度更换输入或补抽样。所有成功慢样本保留。诊断与预热不进入中位数。

Release 使用原有优化开关：IPO、completion batch32、steal scratch、compute lanes8；实验二进制、源码、协议、完整条件顺序先保存散列。先通过现有 runtime/CLI 检查和新增策略/迁移检查，再计时。每个进程完整重算核验，诊断另查 exact_once、工作量、执行归属、输入和预读散列。三种动态诊断任一没有成功窃取，就停止正式采样并保留失败，不写零局部性损失。

总采集预算 900 秒，单进程 60 秒。最多四个动态工作线程或十六个计算工作线程，单个数据区不超过 288 MiB。运行前检查 Linux 无其他计算任务及 Windows CPU 负载不超过 15%；运行间持续检查 Linux 竞争任务，出现冲突停止。不改变其他进程、不关本机。

首次准备后，负载检测为 53%，没有启动实验。该准备目录保留。在新的准备目录使用原有 availability 检查器，最多等待 300 秒，连续三次满足原阈值再开始；条件、样本数和性能判读规则不变。仍未空闲就退出，不用繁忙窗口的数据补足样本。

恢复采集后，前四个诊断通过程序完整核验，但采集器误要求 serial 提供线程池的 exact_once 计数而中止；serial 不经过线程池，该字段按接口应为 null。修正的是采集器校验，不修改被测程序、输入或实验顺序；原四次诊断封存，新目录从头执行全部条件，不纳入正式计时。

WSL1 的逻辑 CPU 掩码不证明物理核心/缓存映射，没有可靠 PMU 时只报告预读线程变化的耗时比及实际迁移。即使差异显著，也不能直接认定全部来自缓存；三个效应不作可相加的数值分解。

新增目录独立封存，Linux 与 Windows 导出逐文件核对 SHA256。报告选代表结果，保留全部重复与生成脚本。
