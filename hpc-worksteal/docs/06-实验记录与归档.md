# 实验记录与归档

> 历史归档设计；真实格式以 tools/lab.py 及 runs 中封存记录为准。当前导出和核验结果见 results/closeout-audit.json、[最终评审与选择](13-最终评审与选择.md)。

## 一次真实进程一份记录

run_id示例格式：`实际带时区时间_W02_worksteal_p08_r03_随机后缀`。预热、smoke、诊断、失败、重试均独立ID，以mkdir拒绝同名；示例不是实际run。batch_id标识一组执行前冻结的计划。

```text
runs/<run_id>/
  config.json              请求配置与输入seed
  metadata.json            完整解析配置、状态、环境、版本、实际线程/绑定、指标
  command.txt              cwd、构建/执行/核验命令，显式白名单环境变量
  environment.json         OS/kernel/WSL、CPU/cache/cpuset、编译器、内存、PMU能力
  build.log                实际构建，或已有不可变构建及校验引用
  stdout.log / stderr.log   原始输出，不编辑
  result.json              程序原始结果（若正常产出）
  correctness.json         参考结果、覆盖检查、误差与判断
  notes.md                 负载、异常、重跑关系、未知项
  checksums.sha256         关闭全部文件后封存，不包含本清单自身
```

诊断可增加trace/counters，失败时文件可以缺少，metadata明确说明，不补空文件伪装已做检查。性能run不复制完整巨大输入，但必须保留确定性生成参数、生成器版本及输入散列；不确定性输入必须原样保存。

metadata至少保存：schema_version、run/batch/experiment、purpose、status、起止时间、exit_code/signal、timeout、failure_reason、execution_order、请求及实际完整策略、问题规模、总工作、source/build/collector版本与SHA256、环境、计时窗口、结果核验与纳入/排除原因。

对于本轮细化后的实验，还需保存：元素输入/成本表hash、task区间hash、初始队列hash、每队列成本单位、S3窃取开关与本地顺序、预触碰/预读worker、单task/每worker/总工作集字节。W01声明相同总工作时对照这些身份字段，不能只看seed相同。

冻结batch记录展开后的全部配置与进程顺序、校准选择依据、process/wall预算、对照配对及停止规则；设计JSON不替代实际plan.json。预算耗尽保留incomplete与缺失配置，不能用零值补齐组。修改方案建立新版本和决策，不回写原计划。

状态分离：执行completed不自动等于correctness=pass；timing/development/warmup/diagnostic分开。未知值null，JSON不写NaN/Infinity，不能用0冒充未测。日志不包含密码、token或全部环境变量转储。

## 版本与封存

源码、构建配置、工具分别完整快照并散列；只记Git commit不够，dirty源同样快照。二进制、编译器版本、全部flags/link参数、实际构建/复用来源绑定到每次run。无真实构建前无binary_id。

封存后不可改原metadata。更正新增amendment与新的索引版本，引用原清单和原因；配置不符的原尝试保留，不重新标成原本想跑的策略。构建缓存只复用验散列二进制，不缓存任务结果。

## 汇总与报告

results/runs.jsonl逐次覆盖全部尝试；groups.json按严格条件聚合；claims.json将结论映射group/run；comparison记录同batch的配对与分母。可以派生CSV，但JSON原字段定义与原始metadata是依据。当前不创建伪造数据行。

分组键包含：机器/环境、源码/二进制、编译、executor、全部策略和实际绑定、workload/规模/seed/偏斜/复用/初始放置、总工作、预热协议、计时口径、诊断状态。不同seed如做跨输入聚合需单列分层分析，不直接冒充重复同配置。

图表保留脚本、输入数据、单位、n及误差定义。原始记录、失败和负收益全部保留；报告引用一次最快值必须明确n=1，不能叫稳定性能。
