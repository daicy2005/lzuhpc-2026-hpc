# 第十二轮：分配、填充与完整FNV成本诊断

2026-10-22，按[冻结协议35](35-第十二轮初始化成本诊断协议.md)完成一次独立顺序诊断。zeroed探针中标量填充占比较小，分配清零与完整FNV更大；overwrite下大量minor faults转移到填充阶段。这是成本定位证据，不是生产应用或窃取加速。本轮不筛选候选，accepted=null，保留第八轮推荐及原构建来源。

## 实际设计

新增[独立C++探针](../tools/init_cost_probe.cpp)与[采集审计工具](../tools/init_cost_study.py)，未改生产src、include、CMake、测试代码及配置JSON。探针依次执行原数组分配、原scalar mix(seed+i)填充、从实际数组读取全部字节的原FNV-1a，最后在计时外逐word检查。无共享数据、散列缓存、新线程、降低精度或减少工作量。

阶段使用noinline边界和getrusage，各墙钟区间包含末尾rusage查询；缺页观测与时间戳也不是同一个瞬间。不能将极短的overwrite allocation看作精确的纯分配成本。自检查零不进入profiling进程。

两个新输入seed91009/N80=40MiB、seed97001/N128=64MiB，两种分配各一次预热，每输入5对AB/BA，共4预热+20profiling。另用第十一轮原Release各做一次完整diagnostic控制，完整参考核验、exact_once、元素数和实际affinity通过；两次只提供原应用数据身份，不比较时间。

这补充了第十一轮留下的问题：继续调整生成器，针对的是zeroed下较小的阶段，不能按生成循环的变化比例推断整个应用收益。对应CS149的Amdahl定律：收益受被改部分原先占比限制。探针占比不是生产应用精确占比，也不是任何新优化的收益保证。
