# 策略与接口契约

> 历史契约草案。当前实际 API/JSON 以 include/worksteal、configs/runtime 和 configs/recommended 为准；命名及诊断差异见 docs/12、[最终评审与选择](13-最终评审与选择.md)。

以下是待实现的语义约定，不是已编译的 API。P1/P3 落地时保留这些边界，可调整类型细节并记录决策。

## 相互独立的决策

| 契约 | 输入 → 输出 | 首批选择 |
|---|---|---|
| PartitionPolicy | 总逻辑区间/预算 → 不重叠且完整覆盖的任务集合 | fixed_grain / balanced_chunks |
| VictimPolicy | worker ID、允许worker集合、失败历史 → victim或无候选 | round_robin / seeded_random |
| StealTimingPolicy | 空闲状态、本地失败次数 → 禁止偷/立即偷/退避/进入等待 | disabled（对照）/ immediate / bounded_backoff |
| MigrationPolicy | victim可转移任务与预算 → 转移批次和合法性 | single / capped_half |
| AffinityPolicy | Linux允许CPU集合/已验证拓扑 → worker到CPU计划 | unbound / explicit |
| PlacementPolicy（额外） | task home、worker集合 → 初始队列 | home / round_robin |

Partition 决定“拆成什么”，Placement 决定“初始放哪”；Victim 决定“找谁”，Timing 决定“何时找”，Migration 决定“搬多少”，Affinity 决定“线程在哪”。Migration 初版只转移任务描述符；不得把移动数据页误说成已实现。NUMA页迁移不在初版范围。

策略不得私自修改完成计数、执行任务、拿其他策略的锁或改变线程数。运行时拥有队列与原子状态并执行转移，策略返回决策；只读观察允许滞后，拿到锁后运行时必须重新验证容量与可偷取范围。

策略组合在启动前检查：线程数正值、CPU无越界/重复（显式一核一线程模式）、grain>0、batch上限>0、victim不含自身（p=1返回无候选）、队列所有权合法。未知配置键和不支持组合报错，不静默退回默认。

Affinity 的请求、调用返回与实际每线程掩码都记录；验证失败则停止该次配置。unbound 不作单核绑定。不得根据 WSL CPU 编号自行声称已验证 P/E 核或 NUMA 关系。

S3-off为steal_timing=disabled，其余设置和S3-on完全相同；S3-on的初始锚点为immediate、round_robin victim、single迁移。disabled不是依赖workload的特判，不跳过完成协议或本地队列。配置与输出同时记录steal_enabled，若它与策略矛盾则拒绝。

## 工作负载契约

同一 workload 的 seed、逻辑元素数量、每元素运算及输入在所有 executor 间相同。改变 grain 只改变边界，不改变每元素 RNG 输入；使用按元素索引可复现的初始化。结果每元素或每逻辑块独立保存，参考计算按固定顺序验证。

compute_uniform、compute_skewed、memory_reuse 为首批名称。纯计算输出必须被核验，防止编译器消除工作；不靠 volatile 把整个热循环改成特殊内存工作负载。memory_reuse 的页触碰、预热和计时区域按 docs/05 明确划分。

元素身份、成本/数据home与任务分组分离。compute_skewed的成本表按元素ID生成，不随队列顺序或运行者变化；W02冻结粒度后仅重排同一任务集合。memory_reuse按固定数据块定义home，W03比较迁移时固定任务划分，不用改变grain同时改变home。具体生成、散列与对照约束见 docs/09。

## 计划 CLI

`worksteal --config PATH --output PATH`；可加 `--list-policies` 与 `--validate-config`。所有执行参数可由配置表达，显式CLI覆盖项写入最终配置；不通过未记录的环境变量隐藏策略。

stdout 输出一个合法 JSON 结果对象，stderr 输出诊断。成功退出0；输入/配置错误2；执行异常3；正确性不符4。超时由采集器标 timeout 并保留实际终止信号，不伪造程序退出码。

2026-10-16实际接口补充：measurement.reference_workers可选，默认1，整数1..128；它只控制完整标量参考核验，不改变被测Pool。并行比较后固定归并计数，输出散列仍顺序执行。correctness新增reference_workers_used/reference_tile_elements。生命周期、计时与验证见[第四轮契约](19-第四轮结果与核验契约.md)；本段优先于历史草案中参考计算按固定顺序执行的表述。

结果至少包含 schema_version、status、resolved_config、timing（setup_seconds、dispatch_seconds、epoch_seconds、end_to_end_seconds）、correctness、metrics_mode。metrics_mode=timing 时不存在的详细计数写null；不能填0冒充已测。

`epoch_seconds` 是工作已准备好、所有worker就绪后的统一释放时刻到全部任务完成；包含任务取得、同步、调度、等待和计算。任务队列放置及线程创建在该窗口外，分别记录；同时给出包含创建/初始化/分发/执行/核验/关闭的端到端时间。不同模式必须遵守相同窗口，不将一方的任务生成算入而另一方排除。

时钟采用std::chrono::steady_clock。主线程在持有启动门状态锁时取得t0，再发布epoch并打开门；没有任务可以早于t0执行。t1为主线程确认全完成后的读取，包含结束通知和主线程唤醒延迟。若另记最后完成worker的时刻，作为completion_seconds单列，不与epoch_seconds混用。零任务也输出实际计时，不用零值伪装时钟开销不存在。

首次实现会用实际命令检查文档与CLI一致。当前 configs/example.json 仅为契约示例，不能声称已有可执行程序。
