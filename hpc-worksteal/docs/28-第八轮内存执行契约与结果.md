# 第八轮：内存执行交错契约与实际结果

2026-10-21。执行依据为测量前冻结的[协议27](27-第八轮内存执行交错协议.md)。测量源码ID为`4c9cdd0f4aacf04acc313a4dda6c2ed1bf2151b37bf3ffad12059a031f4bc6bb`；本文为之后新增的交付说明，不是构建来源快照。

## 为什么可以交错

memory原value(i)对单个元素进行pass→word递推：`x=(x+data[i*words+j]+r)^(x>>7)`，每一步依赖上一步。不同元素的x与数据区间独立。新execute分支每次处理任务内4个连续元素，用4个独立x，按pass→word→lane更新；对任意固定lane，观察到的r/j顺序与原标量完全一致。uint64自然回绕、总读取次数及输出均不变，不复用最终答案或跨pass中间结果。

循环条件`t.end-i>=4`保证4个元素均在当前任务内；每组后i增加4，不跨任务边界，余下0至3个元素进入原value()。grain3等条件可以完全落入标量尾部；metadata中的memory_lanes_used表示选中的最大交错宽度，不承诺每个任务都有完整4元素组。不同任务仍写各自独立output/executors区间，发布和完成检测沿用Pool原协议。

measurement.memory_lanes省略默认1，仅接受整数1/4，bool/float/string及其他数值拒绝。构造函数亦验证取值。compute不使用该参数，used=0；空memory亦为0。1路仍走原标量执行，4路不会改变完整独立标量参考value()/verify()。初始化、home预读、顺序FNV及计时边界未改。

这是利用独立递推链的指令级并行实验；跨元素访存顺序改变，不能声称缓存状态一致，也不根据源码直接断言某种SIMD实现。收益若成立归执行内核，不归工作窃取策略。
