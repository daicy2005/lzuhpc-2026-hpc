# 并发与正确性规范

> 本文是预先规范，不是检查执行记录。真实实现、已通过检查及剩余边界见 docs/12、[最终评审与选择](13-最终评审与选择.md) 和归档 validation.json。

## 必须成立的不变量

1. 每个逻辑任务从未开始到运行中再到完成，恰好执行一次；取消任务另有状态，不伪装完成。
2. 入队/出队/转移受所属队列的 mutex 保护。完成计数原子化不能替代队列同步。
3. 任务结果由执行者独写；主线程观察“本epoch完成”时，所有任务写入都已对它可见。
4. epoch总任务数冻结；队列暂空可能是任务仍在执行或已在迁移临时缓冲中，不等于全局结束。
5. 没有线程在持队列锁时执行任务体、等待其他锁、休眠或调用未知回调。
6. wait具有谓词，epoch代数防止把上轮唤醒当本轮工作；失败/关闭路径能唤醒所有等待者并join。

## 生命周期

主线程创建pool → worker就绪 → 生成并发布本epoch任务 → 就绪屏障与统一计时起点 → 执行/窃取/等待 → 全任务完成或失败 → 主线程收集结果 → 下一epoch或shutdown → join → 销毁资源。

只允许一个外部控制线程提交epoch；执行期间不能添加任务。初版 pool 可重复运行epoch以测试复用，正式重复仍每个独立进程一个run。线程数创建后固定。

完成协议应在实现时单列说明：哪把锁保护 epoch状态/等待谓词，结果写入如何通过原子RMW及完成通知发布给主线程，以及通知与状态改变的先后关系。不能仅写一个 relaxed计数器就认为全部结果可见。可以采用容易证明的默认顺序一致原子与状态锁，先正确再考虑弱内存序。

空任务集由控制线程直接完成，不等待不存在的最后一个任务。少于线程数时，空闲worker仍能识别epoch完成。立即偷与退避策略只能改变等待方式，不能绕过全局完成/失败检查。进入休眠的谓词协议须防止“最后一次通知发生在真正wait之前”的漏唤醒。

## 异常与停止

worker捕获任务异常，记录第一份错误，将epoch置失败，停止开始新任务；已运行任务允许结束。未开始任务标取消，最终结果无效；等待者全部唤醒，shutdown可完成。初版不强制中断任意C++任务，失控任务由采集器进程级超时兜底。

运行时错误、失败任务、被取消任务都保留。配置未通过校验不启动worker；不能在失败路径输出成功checksum或正常性能成绩。

## 检查矩阵

| 类别 | 至少覆盖 |
|---|---|
| 任务覆盖 | N=0/1、N<p、N=p、N不能整除grain；诊断计数每个ID恰好1 |
| 边界 | p=1、p>N、grain=1、grain>N；非法p/grain/CPU/策略名称 |
| 并发 | 多次争同一victim、最后一个任务转移、batch边界、随机短暂停顿扰动 |
| 输出 | 四种executor及合法策略组合对同输入的参考结果；固定归并次序 |
| 生命周期 | 重复epoch、空epoch夹在非空之间、空闲shutdown、任务异常、析构join |
| 所有权 | 输入/闭包存活到join，拒绝运行中修改数据；不同任务输出不重叠 |
| 扩展 | 新victim注册，核心及旧策略未改；重复注册、未知策略拒绝 |

单元检查使用可重现seed；并发压力覆盖多个seed和线程数，超时为失败且保留seed。诊断计数、故意延迟扰动不得进入性能构建。

GCC/Clang普通检查，ASan+UBSan一组，TSan单独一组；工具冲突时不混开。TSan成功不等于证明无竞争，失败也需区分运行环境不支持与真实报告。用受支持Linux环境验证前保持pending；不为此干扰已有光追任务或擅自安装/重启系统。
