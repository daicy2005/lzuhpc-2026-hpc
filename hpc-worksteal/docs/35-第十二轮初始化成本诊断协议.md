# 第十二轮：初始化成本诊断协议

2026-10-22，首次采样前冻结。只诊断，不进行候选筛选、不建立推荐配置。生产src/include/CMake、已有配置及历史原始数据保持原字节。

## 问题与边界

此前workload_initialization合并了分配、清零、首次写入和数据生成，不能从阶段总数推断各自的成本。本轮独立单线程探针依次使用与原程序相同的uint64数组分配、scalar mix(seed+i)填充和低字节优先完整FNV-1a，分别记录墙钟和getrusage(RUSAGE_SELF)缺页增量。zeroed/overwrite是诊断对照，不是第七轮采用门槛的补样。

探针各阶段使用noinline函数，以明确测量边界；这与生产LTO后的函数布局不同。阶段内包含getrusage/计时开销，overwrite分配可以延迟实际页建立。缺页数不等于缺页耗时，也不能证明NUMA、物理核、缓存命中或内存带宽因果。没有PMU数据，不作这些结论。只对每个进程实际连续区间求和再取中位数，禁止相加阶段中位数冒充总量。不把探针结果叫应用或窃取加速。

## 固定预算与正确性

- Linux GCC13，C++20，Release -O3 -DNDEBUG -flto=2，无march=native/fast-math；另建ASan/UBSan -O1 -g诊断版。不新增线程，故不为这个顺序工具重跑TSan或原runtime测试。首份准备因-flto的串行LTRANS警告停止，未采样；保留其源码、二进制与日志，新准备显式指定2个LTO作业。
- 两份探针各运行一次内置自检：word数0/1/2/3/17/4097，seed0/42/UINT64_MAX-2，两种分配，共36例。zeroed自检先查零；随后逐word核验，输出小数组及FNV，由Python独立重算。自检与正式探针阶段严格分开。
- 两个新输入seed91009/N80=40MiB、seed97001/N128=64MiB，每元素512KiB。原第十一轮Release各做一次完整diagnostic控制，固定memory_lanes4/init1/fill1/separate/zeroed/ref4/p16/g4，完整参考核验、exact_once与affinity检查；与探针完整数据FNV一致。这两次只建立数据等价性，不作性能对照。
- 每输入zeroed/overwrite各预热一次，共4进程。每输入5对诊断采样，奇数对zeroed→overwrite，偶数反向；每对按输入顺序进行，共20进程。每个进程新分配、生成、完整FNV、计时后逐word检查；不共享数据，不缓存散列。
- 一次prepare中2个自检；采样批次共26进程=2原程序控制+4预热+20profiling。profiling不是timing，不设采用门槛，不作显著性或全局最优断言。编译每次≤120秒，自检/单进程≤90秒，采样总预算600秒。
- 复用已测应用二进制及其validation、源码/构建快照，不把新collector源码称为该二进制来源。探针编译日志和两份二进制、完整objdump、源码快照均归档；核对zeroed分配中的实际清零和标量生成/FNV依赖链。
