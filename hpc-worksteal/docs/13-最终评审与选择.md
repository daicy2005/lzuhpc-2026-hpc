## 结果与选择

七个已完成批次，共 498 个研究进程，其中 342 个计时样本，其余为集成检查、校准、预热、诊断及三个推荐配置验收进程。源码版本分开，失败 v2 和开发 smoke 未进入排名。

| 任务 | W04 筛选候选 | W05 两个输入胜出对数 | 最终 |
|---|---|---|---|
| uniform | random | 2/5、1/5 | base |
| skewed | random_half | 3/5、3/5 | base |
| memory | random | 1/5、4/5 | base |

晋升条件：每个输入都至少 4/5 对更快，而且候选中位数不超过默认的 95%。memory/991 单独通过，另一个输入失败；不据此替换默认。

base：fixed_grain（compute=64 元素/task、memory=1 块/task）、round_robin victim、immediate、single、显式逻辑掩码 [0,1,2,3]、round_robin placement。skewed 使用冻结 concentrated 布局。完整配置在 [configs/recommended](../configs/recommended)，三个配置都已真实执行并核验输出，见 recommendation-check 批次。

这是预定开启窃取候选集合中保守保留的默认组合，不是全部执行器的全局最佳。固定归属、中央队列和 off 作为机制对照；均匀输入 off 与默认接近或略快，不建议把窃取当通用加速开关。

集中偏斜布局 W02：off 989.04 ms、on 407.39 ms，比值 2.428；spread 1.005、shuffled 1.015。追加独立诊断里，集中布局每 worker 成本由 335.5/67.1/67.1/67.1 百万 mix 变为约 134 百万，成功偷取 343 次，结束时刻跨度从 867.62 ms 缩至 1.42 ms。诊断并非正式计时样本，不用它拆分耗时或跨版本计算收益。

W03 已测每任务 512 KiB、4.5 MiB、288 MiB，相对 36 MiB LLC 为 1/72、1/8、8。两个方向的受控执行者结果没有一致趋势；六个开启窃取动态诊断均未发生成功偷取。home 不匹配可能来自初始放置，不能当作偷取次数。因此当前没有动态窃取造成缓存损失的证据；容量覆盖完成不等于缓存因果已验证。memory_reuse 是有串行依赖的混合访问，也不是已证明带宽饱和的基准。

## 代码与证据边界

- v3 的 Release、ASan+UBSan、TSan 分别通过真实 runtime 与 CLI 检查；每构建 runtime_checks 为 1204 项。增加 test_reverse 仅新增注册单元/构建源，复用 ws_core。
- 生产 C++、接口、测试和 CMake 与 v3 通过版本一致。只读终审未发现推翻当前数据的并发问题；检查不等于形式证明。
- attempts 不包含首次 victim 快照锁失败；busy 包含两次取锁失败，不能把 busy/attempts 当总失败率。capped_half 按快照队列长度取半，再按实际可用长度裁剪。
- static 同样使用本地 mutex/deque。未来扩展 partition 必须保证合法区间；当前布局前未逐项验证非法分区，不宣称恶意或错误插件隔离已完成。
- 原始记录不可重写。analyze.py 已增加冻结顺序、完整重复、实际配置、同组身份、批次二进制和内外层散列核验；closeout-audit.json 核验源码、构建与导出。

复现入口与全部 run_paths 在 [study-summary.json](../results/study-summary.json)；推荐决策在 [selection.json](../results/selection.json)，归档验证在 [closeout-audit.json](../results/closeout-audit.json)。Linux 原件与 Windows 镜像同盘，不等于独立故障备份。
