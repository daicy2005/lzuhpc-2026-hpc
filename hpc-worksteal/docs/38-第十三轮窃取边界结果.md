# 第十三轮：窃取收益取决于布局和可拆分粒度

采样于2026-10-22，2026-10-25完成复核与交付。按[冻结协议37](37-第十三轮窃取粒度与布局协议.md)，180个进程、120次正式计时全部完成。集中布局、grain8/256在两个输入均5/5对胜出，epoch中位数比为2.621～3.059；grain16384没有稳定收益。分散布局也出现epoch收益，但应用总耗时变化小且方向不一致。没有新策略或推荐替换。

## 比较的是什么

使用同一份第十一轮Release二进制，batch32/scratch/LTO/compute_lanes8固定。16个worker、逻辑CPU掩码0..15、round_robin victim、single migration不变。off使用disabled（空闲wait），on使用immediate（允许窃取且空闲yield）。因此结果是这两套策略的净差异，包含空闲行为变化，不能称为剥离其他费用后的纯窃取成本。

compute_skewed前N/8元素成本9K，其余K，K=256。seed100003/N65536的总成本W=33,554,432次mix；seed106013/N98304为50,331,648次mix。grain8/256/16384不改变元素输入、成本、完整递推或最终输出。reference_workers=16，每次完整标量核验所有元素；没有复用输出或删减计算。

对每个grain，concentrated/spread只重排冻结TaskId集合。同grain/layout的off/on初始任务和队列身份完全相同。粗粒度分别4/6任务，两种布局实际队列也相同，因此两布局不能当作独立场景证据。同一输入所有grain/layout/模式的完整输出散列一致。

## 与CS149概念的对应

集中布局grain8/256的初始最大队列工作量是平均值的4.5倍，单位均衡度W/(16×最大worker成本)=0.2222。原始负载集中于前两条队列。诊断中，grain8开启窃取后转移1405/1959个任务，实际单位均衡度变为0.4310/0.4794；grain256转移57/64任务，变为0.6531/0.6667。实际执行归属支持负载转移确实发生，但这些是独立诊断进程，不与正式时间逐段相减或据steal次数单独证明加速因果。

分散布局初始工作单位完全相等，off实际每worker单位也相等，但on的epoch仍更短。诊断中on实际单位均衡度反而降为grain8的0.5476/0.5840、grain256的0.6400/0.8421。这说明“每人分到同样多的mix”不能直接等同于“每人同时完成”：动态调度允许不同执行者完成不同工作量。可能涉及线程运行速度或系统调度差异；本轮没有独立速度校准、物理核映射或PMU证据，不能断言P/E异构、具体核或缓存是原因，也不能把单位均衡度叫CPU利用率。

grain16384只有4/6个不可拆任务。最大任务Cmax分别占W的62.5%和58.33%，Cmax/(W/16)=10和9.333；理想同速处理器下，单任务成本已远高于平均分配单位。诊断中即使出现3～4次窃取，最大任务没有被拆开，实际单位均衡度仍为0.1000/0.1071。这对应CS149的任务粒度与可用并行度：工作窃取只能搬现有任务，不能制造任务内部并行。单位下界max(W/16,Cmax)不等于本机秒数下界，不假设所有worker同速。

细粒度也不是越细越好：本轮grain8比256增加了任务数、队列访问和完成发布机会；没有冻结跨grain推荐采用规则，不能只凭某一格更快就定为新最佳。诊断steal数之差不能换算成精确锁或调度耗时。

另外，concentrated关闭窃取时仍有61440/92160个元素的executor不等于home；这是初始布局与TaskId%p定义的home不同造成的，不是窃取。审计使用初始队列owner重建迁移，single模式逐任务迁移数与steals/moved完全相同，避免误读home_mismatch。
