## 基础设计

初版任务描述符在开始前生成，运行时移动 ID/区间描述符，不搬运底层输入。每 worker 一份队列与局部统计。任务输出写入独立位置，最终按逻辑 ID 顺序归并，防止调度顺序改变结果或引入共享累加热点。

数据内存、任务执行闭包、策略实例的生命周期长于整个 epoch；线程池关闭并 join 后才销毁。worker 的可变策略状态（随机数、失败次数等）归该 worker 独有；不共享一个无保护 RNG。

窃取批次先在 victim 锁下移出本地临时缓冲，释放锁后再进入自己的队列；不同时持有两把队列锁。同一逻辑任务 ID 不因迁移重建或重新随机化。

终止依据固定总任务的完成计数，不依据“刚好看见所有队列为空”。终止、唤醒与失败设计见 docs/04。

S3-off/on使用同一二进制、同一executor、同一队列锁、本地LIFO顺序、完成协议和统计级别，只通过StealTimingPolicy的disabled/启用策略决定是否尝试窃取。disabled仍参与正常epoch等待/结束，不引入更快的串行旁路；没有待生成任务时可等待全局完成。由此比较允许窃取的净效果，不把S1与S3全部差异都归因于窃取。

全局每任务完成原子计数是初版容易证明的协议，也可能在极细粒度下产生缓存行竞争。原子操作、本地锁、队列描述符和间接调用均属于框架成本，不能看到细任务退化就唯一归因于队列锁。是否改成其他完成协议另立对照，不在首次窃取实验同时修改。

## 扩展机制

采用启动阶段工厂注册、运行阶段策略对象的设计。新实现加新 .hpp/.cpp 和单独 register_*.cpp，在构建源清单显式加入注册单元；通用配置解析通过 registry 查询名称，不在主循环或主程序追加 if/switch。

新增文件及构建源清单变化属于扩展；修改旧 runtime、旧 policy 实现、通用解析器才能增加一个同契约策略，则扩展验收失败。注册只在启动时执行，未知/重复名称立即报错。初版编入同一程序，不引入动态库 ABI。

策略调用使用小粒度决策接口；虚调用等间接成本在同框架对照中保留并测量。没有证据时不再制造模板/虚函数双套实现。

## 文件控制

公共头文件只放稳定契约。普通工具函数在所属模块内，不建立泛化的“万能utils”。测试文件按不变量组织，benchmark 按工作负载组织，不为每个策略复制任务体。代码、实验配置与生成结果分别存放；原始记录不作为源码测试夹具随意改写。
