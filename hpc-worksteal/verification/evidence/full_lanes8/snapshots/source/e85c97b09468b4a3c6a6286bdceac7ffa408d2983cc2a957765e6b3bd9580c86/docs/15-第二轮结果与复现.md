# 第二轮结果与复现

2026-10-16。用户要求继续尝试优化。本轮已完成十种构建消融、90个线程/粒度组合、两个新输入的五对留出确认，以及推荐配置真实复跑和对应 sanitizer 检查。完整协议见 [14](14-第二轮优化协议.md)，详细报告见 [第二轮优化报告](../report/optimization/第二轮优化报告.md)。

## 当前选择

| 任务 | 构建选项 | worker/grain | 留出 epoch 加速比 | 含初始化和核验的应用端到端 |
|---|---|---|---|---|
| light | batch32 + scratch | 16/256 | 15.03、14.96 | 3.19、3.39 |
| uniform | LTO + lanes8 | 32/1024 | 13.89、15.81 | 1.26、1.27 |
| skewed | batch32 + scratch + LTO + lanes8 | 32/256 | 14.42、14.29 | 1.23、1.21 |
| memory | batch32 + scratch + LTO + lanes8 | 16/4 | 1.79、1.95 | 1.00、1.11 |

每行依次为seed137/2027，均为base中位数÷candidate中位数，越大越好。八组均5/5对胜出，满足预定双输入门槛。对照是本轮新构建的baseline（p4、compute重任务grain64、轻任务及memory grain1、原标量内核），未拿第一轮旧时间拼重复。

收益并非单一工作窃取策略带来：同p4消融显示八路交错对重计算明显有利，batch32对grain1轻任务有利；随后线程数和grain共同变化。memory未改内核，home划分随参数变化，因此不将其结果称纯调度或缓存因果。LTO单独不一定更快，scratch单独也未显示稳定的大收益；没有把每项修改都包装成成功。

epoch只测已经准备好的线程池执行，应用端到端包含初始化、完整标量核验与关闭线程池，但不含外层配置读取、JSON最终序列化、OS进程启动。采集器还保存elapsed_process_seconds。不能把15倍epoch收益当成整个程序15倍，也不能将多线程数变化当作同核效率。

## 实现约束

batch32的pending只记录已成功完成任务；每32个或取不到任务时发布RMW，等待前必刷新余数。保持seq_cst发布链、状态锁、arrived屏障和异常恢复；不预减未执行任务。scratch仅改变偷取描述符存储，不改两端顺序和锁外回调。lanes4/8每个元素仍做全部原递推，成本不同块和尾部回标量，内存访问内核不变。

十个Release构建全部通过各自冻结检查；最终三种入选构建各有ASan+UBSan、TSan真实通过证据，每个补充sanitizer构建runtime_checks=1448。补充CLI对7/8/9、31/64/65等规模及多个grain使用独立Python递推核验，覆盖八路交错真实路径。最终计时使用的原Release二进制也用这版CLI重新检查，原封存validation不回写。

第一批推荐配置验收把Windows CRLF JSON重序列化为Linux LF；封存字节不重写。审计分别验原配置和已执行配置的SHA，再检查JSON语义相同。后续工具已改为按字节复制配置。这是换行差异，不是参数差异。

## 复现与证据

直接入口：[configs/optimized/README.md](../configs/optimized/README.md)。builds.json同时记录每类的CMake参数、原二进制SHA、快照路径和配置SHA，推荐配置必须和对应构建一起用。新增CMakePresets已通过真实cmake解析及与实测flags逐项核对；不另称从preset全新构建已测量。

研究批次为160+360+96=616进程，470个计时样本；另外4个推荐配置验收进程不参与选择。包括全部较慢成功记录，没有留出后选第二名或增加到通过。Windows导出与Linux原件逐文件验证，三阶段顺序/配置/重复/总工作/输入输出身份均经过核验。

- `optimization/results/optimization-summary.json`：统计、条件、逐对值、完整run_paths和选择。
- `optimization/results/runs.jsonl`：616个研究进程索引。
- `optimization/results/archive-audit.json`：16份构建验证、源码一致性、导出与推荐复跑证据。
- `optimization/results/recommendation-check-*`：4个完整配置复跑及入选Release二进制的补充独立CLI检查。
- `optimization/snapshots`与`evidence/opt-*`：各自源码、构建日志、CMakeCache、二进制和原validation。

重算：`python tools/analyze_opt.py --root .`；验归档：`python tools/audit_opt.py --root .`；生成报告：`python tools/report_opt.py --root . --font C:/Windows/Fonts/simhei.ttf`。运行目录为项目根目录，报告依赖见report/requirements.txt。

本轮是本机有限候选内通过新输入确认的推荐，不证明全局最优。WSL1物理驻留、P/E映射、缓存miss因果仍未证实；单次端到端的主要后续瓶颈仍是初始化和完整参考核验。进一步研究需要单独冻结验证流程或在可核实拓扑的Linux环境做新实验，不在当前结果后追加参数以制造更高倍数。

题面正式提交的DevContainer实建和真实完整连续Session导出仍未完成；本轮不冒充题目已最终提交。
