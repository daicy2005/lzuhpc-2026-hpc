# 第三轮结果与复现

2026-10-16。执行前协议见[16](16-第三轮补充实验协议.md)，完整表格和逐对数据入口见[报告](../report/refinement/第三轮补充实验报告.md)。

36个组合，一预热三计时：144个进程；只有light筛选出新候选，另24个进程完成两个新输入、每输入五对AB/BA确认。共168个研究进程、128个正式计时样本。另4个当前推荐配置使用指定原Release二进制真实复跑通过，不参与选择。uniform/skewed的筛选胜者与第二轮推荐完全相同，不做同配置重复确认；memory未参加本轮参数搜索。

light从runtime/p16/g256改为full_lanes8/p16/g512，两个新输入epoch中位数从1.387/1.918ms降为0.679/0.663ms，分别2.04/2.89倍，均5/5对胜出。应用端到端仅1.107/1.056倍。跨内核与粒度的联合收益，不命名纯调度收益；不把前后两轮倍数相乘当作实测总倍数。

另有20个阶段观测进程：4个旧二进制control、4次预热、12次带标记观测，均排除在正式性能选择外。沿用第二轮配置，完整参考核验占逐样本总时间的比例中位数：light42.3%、uniform96.5%、skewed97.1%、memory40.7%。light和memory还受输入初始化和身份散列影响。下一轮优先研究独立标量完整核验的并行化，需新协议与新对照，当前未实现。

三个既有Release在研究前重新通过runtime_checks和独立Python CLI核验；三个新观测Release也各通过1448条runtime检查与98次CLI调用。阶段/总时间关系、同输入全输出身份及旧/新control任务队列身份均已检查。runtime/workload本轮源码保持，只有app增加phase_seconds字段；旧runtime构建早于lane开关，新观测构建显式关闭交错分支，审计验证标量源码等价。旧sanitizer证据仍属于第二轮二进制，本轮未新增sanitizer声明。

当前推荐为[configs/refined](../configs/refined/README.md)，必须使用其builds.json中指定的第二轮冻结源码/二进制，不能把包含新增app标记的当前源码当作本轮筛选原二进制。第二轮配置和数据保持。原始记录在refinement/runs，阶段观测在refinement/profiling/runs，工具/源码/构建快照及Linux到Windows散列核验均保留。

本轮本机有界实验完成；WSL1掩码不证明物理核心、P/E、SMT或cache因果，双输入门槛不是显著性检验。题面DevContainer实建和完整连续Session导出仍是单独未完成的提交项。
