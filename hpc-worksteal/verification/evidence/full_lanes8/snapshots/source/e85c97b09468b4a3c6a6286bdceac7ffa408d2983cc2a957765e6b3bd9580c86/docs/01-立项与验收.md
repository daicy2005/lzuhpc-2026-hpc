## 官方边界

题面要求：自建工作窃取运行时；任务切分与粒度、victim 选择、偷取时机、迁移与亲和性独立可组合；增加策略不修改已有实现与运行时。设计 benchmark 分开研究均衡、开销、局部性，覆盖远小于 LLC 与远大于 LLC 的工作集；比较后给出有依据的策略组合。题目允许局部性效应接近零。

所有开发和评测基于 Linux。提交技术报告 PDF、可复现代码/环境（推荐 DevContainer），以及一个完整连续 Session 的 Prompt/Agent Response，不含思维链。题面不要求无锁实现，也没有规定最低加速比。

来源版本和摘录见 reference/；以下工程范围与验收门槛是本项目的选择，不冒充题面原文。

## 项目范围

第一版只接受执行前冻结的独立任务集合。任务体可计算或访问数据，但不能再次提交任务、等待其他任务或阻塞于运行时；不支持 DAG 和递归 spawn。各任务有稳定 ID、逻辑工作区间和数据 home 标记，结果按 ID 独立存放。

研究主问题：**固定总工作量时，任务粒度与初始不均衡程度怎样决定工作窃取是否值得使用？** 局部性作为第二层机制，先完成计算型实验再研究。目标按正确性、策略扩展、性能解释依次推进；推荐按工作负载类别给出，不预设一个全能组合。

实现四种执行器：串行直接执行、静态划分、集中队列动态调度、每线程队列工作窃取。额外增加同一工作窃取执行器的关闭窃取配置S3-off，与S3-on组成关键对照；它不是另一套执行器。前三种是解释性对照，不称为工作窃取实现。每个并行对照均支持 p=1，便于拆分框架成本。

这是固定独立任务模型，不代表支持递归生成任务的通用运行时，不直接套用其他工作窃取系统的理论保证。理想同速处理器上可用 max(W/p, Cmax) 解释不可分任务的限制；本机混合核心与系统干扰下，不将成本权重直接当实测秒数下界。

## 完成条件

| 范围 | 验收证据 |
|---|---|
| 核心正确 | 每任务恰好一次，输出等价；空集合、1任务、少于线程数、偏斜任务、重复epoch均检查 |
| 并发生命周期 | 启动/等待/结束/关闭无漏唤醒，异常有明确失败语义，超时保留现场 |
| 策略组合 | 五类策略维度均有独立契约，至少两个可替换选择；非法组合运行前拒绝 |
| 扩展性 | 在测试专用新文件中加入新 victim 策略，原运行时/已有策略文件散列不变，注册后可运行并通过检查 |
| 性能研究 | 均衡、开销、局部性各有明确假设与对照；S3-off/on同框架比较；缓存两端及中间规模，固定总工作 |
| 策略选择 | 按工作负载类别给出推荐及适用范围，验证阶段使用未参与选择的预定输入；不强求一个全能组合 |
| 复现 | 独立构建、原始记录、源码/二进制散列、环境、汇总与图表可追溯 |
| 学习 | 能解释队列锁、终止检测、粒度、缓存与速度变化，不只会运行命令 |

功能正确但没有提速时，报告具体负结果和合理解释，不宣布满足“已获性能提升”；保留朴素基线和全部尝试。

## 暂不纳入

无锁算法、实时优先级、线程抢占、跨进程窃取、GPU、工作线程内阻塞任务、在线自动学习调参。光追接入是后期可选应用，不作为第一版依赖。
