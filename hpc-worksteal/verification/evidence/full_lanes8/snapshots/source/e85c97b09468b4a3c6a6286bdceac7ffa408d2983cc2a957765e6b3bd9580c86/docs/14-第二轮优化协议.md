## 范围与假设

在固定独立任务、带锁队列、原数学内核和输出核验下改进性能。不引入无锁队列、不改算法工作量、不用 fast-math，不声称 WSL1 掩码等于物理核心。新样本另起批次，不与第一轮拼重复。单批 600 秒，单进程 90 秒，若超时/失败保存并停止，不追跑到通过。

四个独立开关（本段在首个性能样本前补齐）：

1. `WS_COMPLETION_BATCH=32`：worker 本地累计完成数，每 32 个成功任务发布一次；取不到任务、进入任何等待前必须发布余数。计数只包含已完成输出；seq_cst RMW 链和状态锁发布仍保留。异常仍取消并等所有 worker 到达，不复用未退出 epoch。
2. `WS_STEAL_SCRATCH=ON`：第一个偷取任务直接返回，额外描述符使用 worker 私有 vector，复用容量；保留锁外策略回调与取出顺序。单任务不需要 heap buffer。
3. `WS_ENABLE_IPO=ON`：通过 CMake 能力检查开启 IPO/LTO，允许跨编译单元内联 mix；计算次数、回绕语义、结果不变。它是编译优化，不冒充调度策略收益。
4. `WS_COMPUTE_LANES=4/8`：交错计算四/八个独立元素，提高指令级并行；每元素递推顺序、迭代数不变。只有同成本块走交错路径，混合成本与尾部回退原标量 value；内存访问内核保持不变。与 LTO 配合的 lanes4/lanes8，以及叠加 runtime 的 full_lanes4/full_lanes8，均在首个性能样本前声明。该收益属于数学等价的内核实现，不冒充调度收益。

默认开关先保留 1/OFF/OFF，性能证据确认后另写推荐构建选项，不偷偷改变旧实验语义。

## 阶段

OPT1：baseline、batch32、scratch、lto、runtime（batch32+scratch）、full（前三项全部）及 lanes4/lanes8/full_lanes4/full_lanes8，十个独立 Release 构建，全部先通过 runtime/CLI 检查。四类：light（K16、grain1）、uniform（K1024、grain64）、skewed（同 K/grain、concentrated）、memory（64 块×512KiB、16 passes、grain1）。seed42，compute N262144，p4；每条件一预热三计时，40 条件、160 进程。选各类最小中位数。

OPT2：每类固定 OPT1 选中构建，seed42；p1/2/4/8/16/32（首个样本前固定，覆盖本机逻辑掩码集合）。light grain1/16/64/256，uniform/skewed16/64/256/1024，memory1/2/4。90 条件、360 进程，每条件一预热三计时；选择各类最小中位数。仅移植配置，未测组合不称更差；grain 改变任务划分与 home，内存参数收益是整体调度/预处理组合，不能命名纯队列收益。

OPT3：只比较 OPT2 最终候选与新构建 baseline 的原参数。未见 seed137/2027；compute N196608/327680，memory48/80块。每输入一预热五对计时，AB/BA 交替，共16条件、96进程。候选在两个输入均需至少4/5对更快且中位数≤默认95%，否则保留默认。不得在看到留出后改门槛、选第二名、增补到通过。

两种粒度的输入/成本/输出散列相同，总逻辑工作相同；相同划分时还核对队列身份。跨二进制比较明确记录 build flags、源码与二进制散列，不以不同二进制当同组重复。build screen 为实现净收益，parameter screen 为联合参数收益，留出为最终配置净收益，不强拆为三个相加分量。

如果最终选择含运行时改动，另建 ASan+UBSan/TSan 实际运行，并核验无窃取、空任务、小于批次、边界32附近、异常恢复、多 epoch、单/多 worker；基础 CMake 配置仍可重现旧完成协议。全部慢成功记录保留。统计保存 n/median/min/max/IQR 和逐对值，不把4/5工程门槛称显著性检验。
