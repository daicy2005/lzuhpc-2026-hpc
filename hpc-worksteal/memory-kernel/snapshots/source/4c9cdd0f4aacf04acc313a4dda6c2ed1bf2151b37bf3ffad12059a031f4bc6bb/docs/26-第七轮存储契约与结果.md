## 为什么可以不先清零

memory的原路径先分配并将全部word清零，再按`mix(seed+全局word下标)`完整覆盖；生成器不读取旧值。新接口`measurement.data_allocation`只接受zeroed/overwrite，省略仍为zeroed。两者均在控制线程分配相同长度、相同uint64_t类型的唯一所有权数组；前者make_unique值初始化为零，后者make_unique_for_overwrite默认初始化，不初始化标量的值。后者不是读取未初始化值来生成输入。

串行填充严格覆盖`[0,n*words)`。并行可选路径按完整元素区间分块：每块begin由`worker*(n/active)+min(worker,n%active)`给出，长度为`n/active+(worker<n%active)`；区间相邻、无交叠且覆盖全部n元素，再乘words得到全部word区间。没有路径在填充/join之前调用identity、home预读、执行或参考核验。

空memory和compute均不分配data，used=none；空memory的data散列仍为FNV空序列，compute仍为null。原2GiB边界及uint64自然回绕保留。分配失败依赖RAII释放已构造成员；线程创建失败时线程容器先析构并join，闭包及所引用成员后销毁，没有故障注入证据。

hash_words只改接收只读span，内层顺序字节FNV完全不改。std::span不拥有存储；调用期间唯一所有权数组和原各vector均有效。所有身份字段、数据字节数、完整独立标量参考核验、输出及预读散列保留；未缓存任何答案。分配、完整生成及首次写入都仍在workload_initialization和app内，没有移动计时边界。
