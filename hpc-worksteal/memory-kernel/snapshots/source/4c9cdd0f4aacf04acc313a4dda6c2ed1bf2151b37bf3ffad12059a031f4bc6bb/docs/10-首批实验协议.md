## 1. 开始条件

开始前必须先满足：P1串行基线、P2静态/集中队列、P3带锁窃取和S3-off/on通过相应正确性检查并引用实际日志；新增victim策略不改核心的扩展验收通过；Linux工具链/二进制/源码已快照，线程掩码可核实。当前这些条件尚未完成。

已有其他长程性能任务结束后才开始本批。若仍有光追复测，等待其自然结束，不终止它、改其亲和性或插入本项目正式负载。文档校验不受此限制。

## 2. W00：先保证能相信结果

五种对照模式共同检查：N=0/1、N<p、不能整除grain、grain>N、短均匀与偏斜输入；每task恰好一次和逐元素输出正确。队列最后一任务竞争、重复epoch、空闲关闭/异常属于独立功能/压力检查，不以性能曲线替代。

可合并多个小case在一个有明确case索引的功能检查进程，实际所有执行都记录；采集器集成最多40个development进程，单进程10s超时。失败立即停止性能阶段并保留现场，不以“还剩预算”继续采样。此处不是对单元测试case数量设上限，超过集成进程预算要在后续新计划说明。

## 3. 只允许一次有界校准

N固定为262144；compute_uniform，seed=42，所有元素成本K。每元素计算内核按docs/09在P1冻结。S0用相同显式单CPU绑定，依次试K=64/256/1024，最多3个独立development进程。

选择第一个正确且S0 epoch处于[0.2,1.0]秒的K。若未出现合格值，或出现首个超过1.0秒值，则停止并记录“校准范围不适用”，为后续新batch修改设计，不能为每个策略分别调工作量。校准仅建立可测时长，不能保证所有并行/极细粒度配置都在该范围。

选择后冻结K、N、seed、全部输入hash和内核版本；不根据候选速度再调整。校准数据不混入W01 timing，不用作候选排名。

## 4. CPU 与计时矩阵

读取Linux实际允许CPU集合，按编号升序取最多前4个，并在所有模式实际核验每计算线程的单CPU掩码；这里只使用逻辑编号，不宣称对应特定P/E核心。

令p0=min(4,允许CPU数)，线程候选为去重后的[1,p0]。S0以主计算线程绑定第一个CPU，其他模式按同一列表前缀绑定。只有1个可用CPU时记录不能验证多核收益，不靠超额开线程冒充并行。

| 变量 | 固定范围 |
|---|---|
| S0 | 1条件，直接计算整个区间，不按grain重复 |
| 并行模式 | S1 / S2 / S3-off / S3-on |
| worker数 | [1,p0]，去重 |
| grain | [1,64,4096]，元素/任务 |
| 问题 | 同一N、K、seed、元素输入/输出 |
| 窃取锚点 | round_robin victim、single迁移；off=disabled/on=immediate |
| 初始放置 | TaskId round_robin到worker，本地LIFO；实际队列hash保存 |
| 编译 | 同二进制、O3、无fast-math/native、相同完成协议 |

p0>1时共1+4×2×3=25个timing条件；p0=1时13个。每条件1次独立warmup、3次timing，最多25+75=100个进程。S3-on/p=1必须正确识别无victim，不报错或自偷。

相同p/g的S1/S3-off/on使用相同初始队列定义；S1内部可用直接静态列表，S3-off/on本地取得路径必须一致。S2使用共享队列，其顺序差异在resolved_config说明。tiny grain增加描述符与输出假共享等成本，不能称为只测了窃取开销。

## 5. 顺序、预热与实际起止

冻结plan时使用schedule_seed=20261015生成并保存全部配置ID与进程执行顺序，不能只存seed。先按预定顺序各做1次warmup，再执行3个timing block，每个block每条件一次，以预定打乱/轮换顺序分散先后效应。warmup距timing可能较远，不宣称保证目标缓存热态。

首批不在进程内运行额外warmup epoch。测量epoch=1，计时边界按docs/03主线程统一释放至确认完成；端到端仍包括准备、分发、核验与关闭。S0基线和全部候选都保存本进程逐元素结果核验，核验不计epoch但计端到端。

无论排队/分发是否昂贵，都单列setup/dispatch，不能在报告只强调epoch而隐藏真实一次性调用成本。极短并行epoch可能受唤醒/时钟开销影响，保留原值和限制，不单独给某策略重复更多次来提高好看的精度。

## 6. 诊断与预算

全批进程上限：40个W00集成进程+3个校准+100个W01预热/计时+最多4个诊断=147；不含此前P1/P2/P3已有功能检查，不把上限写成已完成次数。真实计划按实际通过检查、p0及校准生成更小清单。

首批总wall预算900s，从W00开始至最后进程结束（含准备/核验/采集），W01单进程30s超时。预算到期停止启动新进程，必要时终止当前进程并记timeout；计划状态incomplete/budget_exhausted，不伪称完整实验。普通失败/质量不符则直接停止，不能事后补跑到成功。启动下一进程前核对剩余预算，采集器保留退出/封存时间。

诊断最多4个独立进程：在p0、grain1和grain4096处各跑S3-off/on一次，固定输入追踪完成覆盖、实际转移与各worker成本。若p0=1，诊断仅检查无victim分支，不用于迁移结论。诊断细项不从timing值中相减。

900s或147是资源边界，不是必须用满的配额。预算不足的组不填n=3；重试需新run和理由，新完整确认批次另立计划。
