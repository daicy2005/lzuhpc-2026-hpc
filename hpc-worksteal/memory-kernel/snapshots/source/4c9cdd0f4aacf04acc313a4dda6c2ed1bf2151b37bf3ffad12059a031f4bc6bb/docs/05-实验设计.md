## 基线与共同条件

S0 串行直接执行；S1 静态分配；S2 集中队列动态调度；S3-off/on为同一工作窃取执行器关闭/开启窃取。共有四种executor、五种对照模式。各方案使用同输入、同总逻辑工作、同任务计算内核、同编译设置和计时窗口。粒度改变只重划分工作，不固定任务数再增加任务体工作。

S3-off/on必须保留相同二进制、本地队列锁、LIFO顺序、初始放置、完成协议、亲和性和指标级别，只切换窃取许可；策略执行本身的费用属于该开关的净效果。S1与S3比较反映整套执行方式差异，不能全部归因于steal。S0直接处理整个逻辑区间，不为每个grain复制同一串行数据点。

线程曲线先1/2/4/8，后根据实际允许CPU扩展；不硬编码本机32线程为所有平台默认。混合核心/SMT/NUMA与WSL拓扑仅在验证后描述，CPU掩码实测失败不纳入该绑定组。

默认C++20、O3、严格浮点、同编译器，使用pthread；无fast-math与native。比较编译参数需独立实验，不与调度选择同时改动。详细事件统计、硬件采样、sanitizer分别diagnostic；正式只启用必要计时、结果核验和每worker低频汇总。

## 局部性实验的约束

先采集cache拓扑和允许CPU。LLC可能按簇共享，必须标明使用哪个已验证共享域；读不到时以绝对字节扫规模，并将LLC比率标unknown，不能宣称已覆盖题面两端直到有可信容量依据。

预定规模覆盖每任务工作集远小于/远大于相关LLC两端，并在可行时覆盖中间；同时报告每worker与总活跃工作集，不能只按总和大于LLC就认定任务本身远大于LLC。初始候选可按每任务0.125×/1×/8×LLC提出，实际比例、并发任务数及总量在batch前核对容量后冻结。比例本身不是缓存驻留证明；内存容量不足时使用更少worker/任务或记录未覆盖，不默默缩小后仍声称满足题面。

任务访问自己固定数据块，多次重用形成可观察局部性；home绑定固定数据块，不随本次grain或偷取结果重算，且只表示逻辑归属，不等于硬件缓存所有权。migration改变执行者但不改变地址。W03中固定grain，避免同时改变数据home。页预触碰、warmup由哪些线程执行、warmup后是否立即计时必须冻结；使用独立新输入的进程重复，不能让某策略总拿到热数据。

计时外cache预热必须对全部方案明示一致，同时报告冷启动/端到端；不能预先计算并复用任务最终结果。可设“无数据复用”的对照，但它改变访问模式，只作为机制对照，不能与有复用组当同工作排名。

一次独立进程warmup只提供可记录的运行历史，不保证下一进程的数据地址/页/缓存驻留状态；目标数据预触碰与复用必须在同一计时进程内、按配置由指定worker完成。W03a固定操作比W03b更强受控，但线程速度、缓存共享及系统负载仍可能混杂，不能单凭耗时证明“发生了cache miss”。

若无steal，不能用该次运行证明迁移代价；若无PMU，仍可报告耗时及诊断steal/执行归属，但“缓存miss导致”保持假设。单独的受控同核/跨核访问微实验可帮助解释，不能直接等同完整运行时的局部性成本。

## 计量与诊断

主指标epoch wall time；另列setup、dispatch、端到端。线程创建、输入初始化、队列分发和正确性核验是否包含，严格按docs/03记录。S0的epoch覆盖直接计算，S1/S2/S3覆盖相同计算和各自调度；避免计时起点晚于任何任务开始。

诊断记录每worker完成任务数、执行时间、空闲区间、窃取尝试/成功、转移数量和home不匹配数量。时间区间应有互斥状态定义；任务数不等于工作量，home不匹配不等于真实cache miss。详细跟踪有观察开销，用相同输入单独跑，不直接从timing总时间减出“精确三部分”。

额外报告每worker完成的固定成本单位、首任务/末任务时刻及计算分布；动态调度后每次归属可能不同。任务体计时之和是诊断构建的观察，不替代静态成本表，也不能与未插桩timing逐项相减。W01极细grain可能受全局完成原子、假共享、元数据访存影响，不能自动归因于deque锁。

硬件计数器可选，必须保存可用性、event、范围和复用比例；不读取到时写null。三效应存在交互，报告条件对照和证据强弱，不强加总耗时=三项独立可加模型。

## 重复与选择规则

调优每配置先1次独立预热（purpose=warmup）后3次timing；确认/留出每配置1次预热后5次独立timing，预热不入统计。进程内预触碰和预热epoch另有配置，不能与进程级warmup混称。预热不能保证恒温或稳定缓存。

筛选阶段按预定block顺序轮流执行各配置，不连续执行某候选全部重复；确认时一对包含基线/候选各一个相邻进程，5对内AB/BA顺序预先冻结并尽量平衡。独立进程预热单列在配对前，不能从相邻配对中挑对候选有利的值。不存在“精确同时同温”的保证。

基线与候选交错，按预先生成并保存的顺序平衡先后位置，不随结果调整；每次记录真实execution_order。单个进程不与其他本项目计时重叠；本机已有长任务未结束前不启动正式WorkSteal性能实验。后台负载无法独占时明确披露。

全部有效重复给出n、中位数、min/max、IQR（(n-1)q线性插值）。失败/超时/输出不符/绑定验证失败不当作成功成绩，理由写入，不覆盖；单纯慢不是排除条件。

默认工程保留门槛：确认5对中至少4对更快，中位耗时降低至少5%，全部正确性通过；范围重叠、选择成本与复杂度仍单列说明。此为预定工程门槛，不是显著性检验。候选未达门槛维持较简单基线，不无期限重复到出现有利样本；修改门槛只对未来新batch生效。

上述门槛只决定是否用额外复杂策略替换原方案，不决定实验是否有价值或项目是否完成；没有提速不写成已满足题面性能目标，但正确且可解释的负结果仍进入报告。

加速比分清：整体比值T(S0)/T(executor,p)；同executor/同策略算法下并行比值S_p=T(executor,1)/T(executor,p)，对应E_p=S_p/p；同p的策略比值T(control,p)/T(candidate,p)不用于计算并行效率。涉及亲和性线程列表前缀、总工作、粒度和输出的关系必须说明；不同CPU组成或后台条件限制推断，不能把混合算法总加速直接除以线程数。
